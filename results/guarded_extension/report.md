# M22: guarded-expression accessibility comparison

**Registered descriptive guarded support: False.** Strict fresh primary passes: ordinary 0/6, overwrite 0/6, guarded 0/6.

The fixed protocol compared a conditional expression extension with a material-matched unconditional extension and the existing ordinary mutation grammar. Sources are the preserved M15 parent, M15 child and known M10 threshold-readout variant in the unchanged M18 VM. They are related historical backgrounds, not independent random origins. 256 fresh random M1 bodies are baseline controls, not a sustained random-founder evolution arm.

## Registered design and novelty accounting

768 endpoints / 3,072 unselected opportunities per arm; three or five opportunities per draw; same source and initial RNG seed within each trio. Every extension appends a payload and either SELECT(old,new) with random condition/polarity or COPY(new). Payload, length, active-writer choice, port maps, seeds and RNG trajectory are identical in the extension pair. The terminal wrapper differs. All ancestral expression prefixes remain intact. Each payload has a 50% chance of reusing a uniformly random private expression through COPY; otherwise it uses the unchanged generic node grammar. No favored writer, gate, maze coordinate or threshold expression was installed.

Preserving old code is not preserving old behavior: changed recurrent state, quiet termination and resource use can still lose skills. Guarded versus overwrite tests the selector package at equal code length, while ordinary differs in edit scope/material. No selection occurs between these opportunities. This is a local accessibility assay, not evidence about many generations of accumulation.

All arms saw the same 712 fresh development inputs. The frozen nonselectable archive has 103 aliases / 73 distinct genomes, including all thirteen preserved references, known M10 threshold, M20 nominees and M21 noncontrol diagnostic models. These extra diagnostics are comparisons, not injected founders. Novel units subtract the entire archive on the SAME cases. Intact solver controls are excluded from that novelty union.

Fixed primary/exploratory roles for each arm/source/depth were committed and pushed before independent 1,680-input confirmation. The best development random control was also frozen. No final-data reselection. Strict pass requires ALL correct source responses, zero false reachable no-path, at least 90% of a NONEMPTY A0 correct-disconnection set and a complete new skill unit beyond source AND archive. Source-preserving recovery of archive skills is reported separately from novelty. A novel complete unit can combine individual responses already handled by different archived models; individual-input novelty is reported separately.

## Posthoc acceptance sensitivity

The absence of retained additions is not solely the 100% retention rule. On the saved development proposals and fixed confirmation nominees, relaxing retention to 95%, 90%, 80% or 50% of both overall source-correct responses AND every nonempty source skill class still produces zero archive-novel complete-unit passes in all arms. This remains zero when the additional A0-disconnection gate is removed. With all source-retention requirements removed, the short guarded specialist above is the only final nominee with a novel complete unit; it fails the A0 gate as well. These are POSTHOC descriptive checks in retention_sensitivity.json, with zero new executions or reselection; they do not replace the registered primary endpoint.

## Reviewed interpretation and next recommendation

The registered outcome is negative: preserving ancestral expressions as syntactic branches did not yield an additive solver in this assay. Conditional SELECTs preserve full source performance more often than matched unconditional exposure (10 versus one of 768 development proposals), but that is still only about 1.3%. The ordinary grammar retains source responses in 194/768, about 25.3%. The ordinary contrast is not an isolated selector test: ordinary variation can edit private unused nodes, while every extension puts a new wrapper at an active writer’s terminal. That difference makes structural extension more exposed to the recurrent dynamics. It is not evidence that SELECT itself is harmful.

The ten distinct guarded nominees exercise BOTH old and new outermost choices with unequal values on the sampled histories. Failure is therefore not explained by all tested branches remaining silent. Conversely, a new internal state or an exercised branch need not contribute to a correct path: it can feed an irrelevant writer, change quiet timing, or damage a useful signal. The measurements establish branch accessibility and rare retention, not successful integration. The short novel maze gives another preserved acquisition with substantial regression; it does not establish cumulative algorithm construction.

Crucially, M22 did NOT test disabled-at-birth extensions, point adaptation of their selectors under selection, or persistence over hundreds of selected generations. It sampled random, initially switching branches followed by three/five unselected structural opportunities. The result does not justify scaling that exact unselected policy, and it does not settle the user's hypothesis that protected complexity, regulation, time and pressure can grow a solver.

My recommendation is a separately registered **neutral-birth, selected-activation campaign**. A new branch would initially be disabled and leave the old writer visible; selection could then mutate its payload and activation using the existing generic operations and ordinary local/internal signals. Verify the initial embedding under the unchanged read/dispatch/tick limits first, with its real work/memory cost: even unused code is not operationally free. After that software/mechanism gate, run a bounded 60–90 minute comparison with matched material/evaluation controls, persistent population/RNG histories, retained-skill pressure, and frozen choices before independent confirmation. This would directly test accumulation and activation over generations. It must not install a favorable case-specific gate, known path primitive or graded-mask chooser. Favorable neutral initialization is a NEW declared experimental condition, not an M22 finding or a promise of success.

The existing SELECT/gating grammar can express such protection; no new solver instruction is needed. The research remains random-origin, with explicit inherited and phase-only ancestry. The rare viable variants and new specialist are preserved; fresh random baseline performance remains very narrow. Fresh confirmation here uses new layouts from the familiar generators, not unrestricted maze-domain generalization. No M23, long run, recombination, cloud compute or solver injection has been launched or authorized. Future audits use new packets and preserve all original seals.
