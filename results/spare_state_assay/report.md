# M17 spare-state duplication assay — audited results


**No spare-state advantage was demonstrated in this assay.** All four fixed
nominees in each arm fail the registered combined endpoint on independent fresh
confirmation. The reference gate is nonvacuous. Neither development nor final
nominees provide even the weaker combination of a target upstream pair and a
correct disconnected response without false claims. This is a limited negative
about these two related neighborhoods and three/five-edit proposals, not a verdict
on sustained random-origin evolution or on whether ten channels can express a solver.

The architectural extension itself behaves as intended: empty embeddings preserve
legacy outputs, stopping decisions and charged work, with explicit extra memory.
However, adding writable state did not make it productively participate in the
selected organisms' output. All four spare nominees have the same output masks
and statuses as their own anchor on all 1,680 confirmation inputs. The two parent
nominees also match every step count; the child nominees differ in step counts on
128 inputs while retaining exactly the child's masks/statuses. Additional state
therefore affected execution cost/timing without new solving capability here.

Of 1,024 spare proposals, only 46 (4.49%) have spare state in the conservative static
backward dependency cone of output or explicit halt. None of the four selected
spare nominees does.756 proposals have nine active writers and 268 have ten; maximum
instruction count is 134, below the 256 cap, and all 1,024 initial spare copies were
made. Capacity was available. It was usually disconnected from the output dataflow.
This is a post-hoc static finding, not a causal ablation: global quiescence and work
budgets can still change through channels outside that cone, and a static path
can overestimate what actually executes.

There is one useful specialist restoration in the overwrite arm, but it recovers
a known repertoire. Its two parent-derived nominees solve 26/256 ordinary bases
versus 20/256 for the actual parent, gaining 8 and losing 2; they lose 32 parent pairs
and do not solve the 16 target pairs. One gained route has 17 edges; others have 3, 4, 6,
6, 6, 8 and 14 edges. Both nominees match protected anchor/0 and quota_parent in mask,
status and steps across all 1,680 inputs. Thus these are new descendants that recover
an existing protected behavior, not a new portfolio capability or general solver.
They solve 1/82 ordinary bases with routes 16+ edges; spare nominees solve 0/82.

My recommendation is to address **how copies become connected**, before another
blind capacity increase. A separately registered generic connected-duplication
prototype should test whether a copy can inherit its donor's initialization and
replace an existing read connection while preserving the original computation.
M17 copied writer rules but left spare channels initially zero; copying a seeded
C0/C1 writer is consequently not an exact copy of its initialized dynamical process.
That is a design limitation to test, not an established explanation for the failure.
Quiescence and fixed-work-budget effects must also be measured; do not assume an
activated copy is neutral merely because its equations match.

If that generic operation can be validated without routing knowledge, it provides
a better-founded starting point for a bounded sustained evolution comparison,
where connected copies have time to diverge and neutral variants can survive.
M17's three/five edits do not test that timescale. Any follow-up must preserve
random-origin ancestry, use unchanged controls and exact retained-skill criteria,
and freeze choices before fresh confirmation. No next prototype, long run,
recombination, cloud compute or known-solver injection is launched by this report.

Joint primary passes: **overwrite 0/4, spare 0/4, unchanged 0/4**. Fresh reference endpoint eligible: **True**.

## Representation and observed costs

Two initially inactive channels preserve legacy behavior exactly. Same primitive operations, 256 total instruction cap, 256 ticks/read/dispatch limits; extra memory 8 bytes/site + 152 bytes metadata. Activated extra writers can change global quiescence and consume budget even before their values feed old writers. The treatment combines spare state and accessible port/mutation domains; it does not isolate every mechanism.
