# M26: saved-record evolvability audit

The user's October 23 "Proceed" authorizes the saved-training audit recommended in
M25. This is a new descriptive analysis packet, not an evolutionary phase. It uses
only immutable M25 training rows, metadata, ancestry and selection/birth decisions.
M25 confirmation is already known; no result here is independent confirmation.

## Questions and definitions fixed before the scan

1. Among new M25 mutant identities, count first training exposure successes on
ordinary reachable perfect and cyclic/random mazes with shortest routes of at
least eight edges. A complete base requires correct shortest paths in BOTH saved
orientations. Report individual-pose successes and 16+ routes separately.
2. Novelty is relative to the 14 protected references evaluated on the IDENTICAL
panel. Distinguish a new complete two-pose combination from the stronger case in
which at least one pose is unsolved by the collective reference input union. The
100-model final archive was not evaluated on these panels and is not a comparator.
3. Compare actual genetic parent and exact root only when queried on that panel;
otherwise record missing comparison. Report gains, losses, false reachable no-path
claims and correct disconnection retention; inherited abilities are not discoveries.
4. Trace immediate next-selection survival, offspring born after that evaluation,
subsequent training exposures, archive presence and final live descendants. Separate
new identity, changed genotype, exact final genotype match and genealogy. Final-round
newborns with assessment but no next training are right-censored, not failed variants.
5. Scan later training exposures too: rotating panels can reveal a capability that
was not measurable on the first panel. Repeated fixed-bank successes are exposures,
not repeated independent discoveries. Export case identifiers for all novel hits.
6. Reconcile every prospective append with its actual parent and both admission
bounds: total instructions+3 <=128 and selected writer nodes+3 <=31. Instructions
include one dispatch per active writer. Cross-tabulate actual opportunities with
same-panel parent longer-route performance. This is exposure accounting, not proof
that changing capacity would cause a gain.

## Integrity, resources and limits

Read SQLite through mode=ro, query_only and a read transaction; never instantiate
a production Journal writer. Do not import inference, environment generators or
selection code. Verify all 507 M25 completion files and 18 local records before and
after, plus journal receipt/input/checkpoint hashes and the existing stage chain.
Keep all old seals, journals and layouts unchanged. No inference, new layouts,
selection replay/reselection, new evolution, AWS or external APIs are authorized.

Run one sequential local analysis worker, bounded at 30 minutes, 4 GiB sampled RSS,
512 MiB new packet storage and the existing 16 GiB free-disk floor. Stop and preserve
any failure packet. Focused synthetic saved-row tests and a separate independently
implemented first-exposure verifier must pass. Record actual wall/CPU/RSS costs,
source hashes and output hashes. Register and publish these definitions/code before
the full scan. Seal this NEW packet only; never reseal or overwrite M25.

Policy comparisons are descriptive exposures in three related, already-diverged
pairs. They are not significance tests or isolated causal effects. Finite training
panels cannot establish general solving or global absence of an ability. A negative
scan can motivate an accessibility/capacity assay but cannot close random-origin
research. No next experiment is authorized by this audit.
