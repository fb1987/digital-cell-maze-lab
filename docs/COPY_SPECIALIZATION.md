# M20: bounded copy-specialization accessibility assay

## Authorization and hypothesis

The user said “Proceed” to the M19 saved-history recommendation: test copy-specialization before another sustained search. M19 showed that most actual training additions survived and reproduced, but ancestral skills were lost. M20 asks whether restricting variation to a copied computation and its existing reader makes additive changes accessible. This is a fixed mutation-neighborhood assay, with no population evolution, intermediate selection, sexual recombination, new inference primitive or known-solver injection. No experiment beyond M20 is authorized.

## Matched variation

512 paired draws per anchor, alternating three and five generic edit opportunities after the initialized copy. Thus each arm has1,024 proposals and4,096 edit opportunities:2,048 endpoint proposals overall. Every opportunity is charged, including genotype no-ops. Intermediate genotypes/events/RNG states are saved but not evaluated or selected; endpoint results do not establish monotonic paths through intermediates.

- `generic`: the exact M19 ordinary seven-mode mutation kernel, selecting any of ten writers.
- `local`: the SAME kernel except the initial writer-selection draw chooses uniformly between the copied writer and its original reader. The reader’s full writer/ports may change; this is broader than changing only its gate. Every other writer, port map and initialization tag must remain bitwise unchanged throughout the walk. The copied writer can be deleted/reactivated using the common existing grammar.

The adapter replaces only the frozen kernel’s first writer draw; there are no fitness-based retries. Donors for within-genome block copying remain generic. Later RNG histories can diverge through different branches of the same kernel. The comparison is a mutation-scope package, not isolated evidence about regulatory gates, extra capacity or selection. Generic variation may activate the other spare slot; local variation cannot edit it. Both arms have identical inherited copy material and hard capacity, not identical realized expression or CPU.

Runtime is unchanged: ten channels, at most256 instructions including active writes,31 nodes/block,256 ticks,4,096 reads/site and32,768 dispatches/site. All execution, premature budget stops, memory and output work count. BFS/oracle data enter fitness/grading only, never candidate inference.
